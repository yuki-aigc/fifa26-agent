# FIFA26-Agent 自动化测试方案

> 生成日期: 2026-06-02  
> 当前测试覆盖率: **0%**（无任何测试文件）  
> 目标: 用最小投入覆盖最高风险代码路径

---

## 一、现状分析

| 层 | 技术 | 当前测试 | 风险 |
|----|------|---------|------|
| 后端路由 | Fastify | ❌ 无 | API 合约变更无感知 |
| 业务服务 | TypeScript | ❌ 无 | 逻辑回归无法自动发现 |
| AI 分析 | Kimi工具调用 | ❌ 无 | 提示词变更导致结构失效 |
| Firo签名 | RSA-SHA256 | ❌ 无 | 签名错误只在运行时暴露 |
| 前端组件 | React/Vite | ❌ 无 | UI 回归依赖人工测试 |
| E2E 流程 | 浏览器 | ❌ 无 | 完整购彩分析链路无保障 |

---

## 二、推荐测试栈

### 后端
| 工具 | 用途 | 理由 |
|------|------|------|
| **Vitest** | 单元 + 集成测试 | 与 Vite 生态一致，支持 ESM，速度快 |
| **@fastify/inject** | 路由集成测试 | Fastify 内置，无需真实 HTTP |
| **better-sqlite3**（内存模式） | 测试 DB 隔离 | 无需 mock，真实 SQL 逻辑 |

### 前端
| 工具 | 用途 |
|------|------|
| **Vitest + @testing-library/react** | 组件单元测试 |
| **Playwright** | E2E 流程测试 |

---

## 三、测试分层策略

```
E2E (Playwright)          ← 少量，覆盖核心用户旅程
    ↑
集成测试 (Fastify inject)  ← 中量，覆盖所有 API 路由
    ↑
单元测试 (Vitest)          ← 多量，覆盖纯函数逻辑
```

## 八、测试基础设施搭建步骤

### Step 1: 安装依赖

```bash
# 后端
cd server
pnpm add -D vitest @vitest/coverage-v8

# 前端
pnpm add -D vitest @testing-library/react @testing-library/jest-dom jsdom

# E2E (根目录)
pnpm add -D @playwright/test
npx playwright install chromium
```

### Step 2: 配置文件

**`server/vitest.config.ts`**:
```typescript
import { defineConfig } from 'vitest/config';
export default defineConfig({
  test: {
    environment: 'node',
    coverage: { provider: 'v8', reporter: ['text', 'lcov'] },
  },
});
```

**`vite.config.js`** 增加 test 配置:
```javascript
test: {
  environment: 'jsdom',
  setupFiles: ['./src/test/setup.ts'],
}
```

### Step 3: 添加 npm scripts

```json
// server/package.json
"test": "vitest run",
"test:watch": "vitest",
"test:coverage": "vitest run --coverage"

// 根目录 package.json
"test": "vitest run",
"test:e2e": "playwright test",
"test:all": "pnpm test && pnpm --dir server test"
```

## 九、Mock 策略

| 需要 Mock 的对象 | Mock 方式 | 原则 |
|----------------|-----------|------|
| Firo API fetch | `vi.mock('node-fetch')` / `vi.stubGlobal('fetch', ...)` | 签名测试除外，均 mock |
| Kimi LLM 调用 | `vi.mock('@earendil-works/pi-ai')` | 固定返回标准工具调用结构 |
| SQLite DB | 内存 DB `':memory:'` | 不 mock，用真实 SQL |
| 时间 `Date.now()` | `vi.useFakeTimers()` | 签名时间戳测试用 |

## 十、优先级与工作量

| 优先级 | 测试项 | 工作量 | 价值 |
|--------|--------|--------|------|
| P0 | Firo RSA 签名单元测试 | 2h | 防止鉴权静默失效 |
| P0 | AI 工具调用解析测试 | 3h | 防止 LLM 返回格式变更 |
| P0 | `/api/lottery/*` 路由集成测试 | 4h | 保障竞彩核心 API |
| P1 | Elo 预测逻辑单元测试 | 2h | 数学准确性保证 |
| P1 | OddsCell 组件测试 | 2h | UI 渲染正确性 |
| P2 | 竞彩 E2E 流程 | 4h | 完整链路回归 |
| P2 | 准确率统计单元测试 | 1h | 边界值处理 |

## 十一、CI 集成建议

```yaml
# .github/workflows/test.yml
name: Test
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - run: pnpm install
      - run: pnpm --dir server test:coverage
      - run: pnpm test
      # E2E 仅在 main 分支运行（节省 CI 时间）
      - if: github.ref == 'refs/heads/main'
        run: pnpm test:e2e
```
